## 二、标题规则

### Editorial

Editorial 按全字符计数：汉字、数字、英文字母、标点各计 1；不能用空格凑数，也不能添加无意义标点。

| 页面 | 模板 | 行数 | 字符限制 | 页面专属禁止事项 |
|---|---|---|---|---|
| P1 | M01 | 正好 2 行 | `6–7 + 5–6` 或 `5–6 + 6–7` | 两行不得等长；两行字体、字号、行高、字重必须一致；断句不能破坏语义 |
| P2 | M02 | 正好 2 行 | `6–7 + 5–6` 或 `5–6 + 6–7` | 两行不得等长；不得以一大一小字号制造层级；断句不能破坏语义 |
| P3 | M03 | 正好 2 行 | 固定 `4 + 5` | 不得改变固定行长 |
| P4 | M05 | 正好 1 行 | 固定 6 字 | 不得折行 |
| P5 | M06 | 正好 2 行 | `5 + 5` 或 `6 + 6` | 两行必须等长 |
| P6 | M07 | 正好 2 行 | `5 + 6` 或 `6 + 6` | 第二行必须 6 字 |
| P7 | M09 | 正好 2 行 | 固定 `6 + 6` | 两行必须等长 |
| P8 | M15 | 上、下两块 | `4 + 4` 或 `5 + 5` | 上下必须等长；禁止 `4 + 5` 和 `5 + 4` |

所有页面还禁止孤字、孤词、自动第三行、语义断裂、浏览器实际渲染与规则不符。标题不合格时，Editorial 共享规范要求停止，不得生成整体框架审核图。P1 的标题语义方向另由《小红书正文标题与P1封面标题配对规范_V1.0.md》管理，不在本次指定来源中展开。

### Swiss

Swiss 标题容量按中文汉字计数，标点不计；每页必须只有一个显式换行，形成正好两行。禁止单行、三行和自动折出第三行。

| 页面 | 模板 | 行数 | 第一行 | 第二行 | 页面专属禁止事项 |
|---|---|---|---|---|---|
| P1 | S01 | 正好 2 行 | 5–6 字 | 7–8 字 | 第二行必须严格长于第一行；卓特清雅体 156px；禁止缩字 |
| P2 | S02 | 正好 2 行 | 6–7 字 | 5–6 字 | 不得超出容量或破坏断句 |
| P3 | S06 | 正好 2 行 | 5–6 字 | 5–6 字 | 不得超出容量或破坏断句 |
| P4 | S05 | 正好 2 行 | 5–6 字 | 5–6 字 | 不得超出容量或破坏断句 |
| P5 | S03_G3.7-B_POSTER | 正好 2 行 | 5–6 字 | 5–6 字 | 不得超出容量或破坏断句 |
| P6 | S10 | 正好 2 行 | 5–6 字 | 5–6 字 | 不得超出容量或破坏断句 |
| P7 | S07 | 正好 2 行 | 5–6 字 | 5–6 字 | 不得超出容量或破坏断句 |
| P8 | S12 | 正好 2 行 | 5–6 字 | 5–6 字 | 不得超出容量或破坏断句 |

P2—P8 使用 Swiss 模板默认无衬线体，不继承 P1 清雅体。所有标题都不得通过缩小字号、修改模板或隐藏溢出来规避容量门控。P1 的语义方向同样委托给《小红书正文标题与P1封面标题配对规范_V1.0.md》。

## 三、P1-P8 页面职责

### Editorial

| 页面 | 职责 |
|---|---|
| P1 | 强冲突封面页：建立第一眼点击理由，只保留一个具体职业困境或核心矛盾，并配置一张主视觉图。 |
| P2 | 真实场景与视觉证据页：用真实工作过程或最强案例图证明问题存在，建立职业共鸣。 |
| P3 | 核心判断与解释页：提出一个明确判断，给出理由或成因，以图文双栏展开。 |
| P4 | 清单、问题或关键判断页：结构化列出单一观察角度的检查点，不依赖图片。共享规范允许 4—5 条，但条目数必须服从终稿和模板合法字段。 |
| P5 | 多图证据墙：用同一视觉体系的 2×2 四图和四条标签，一一呈现四个切面或证据。 |
| P6 | 阶段结论与结构化总结页：归纳 P2—P5，从表面现象进入机制，不重复 P4 清单。 |
| P7 | 强观点与传播金句页：只保留一个最值得收藏或转发的判断，以大字号和强留白收束。 |
| P8 | Before / After 对比收口页：呈现旧认知与新认知或错误与正确，不引入新核心观点。 |

### Swiss

Swiss 搜索型和推荐型共用模板和页面结构，但从终稿提炼内容时使用不同内容适配语义。

| 页面 | 共用结构职责 | 干货搜索型内容落点 | 干货推荐型内容落点 |
|---|---|---|---|
| P1 | 问题与核心答案入口 | 明确搜索问题并立即给出答案方向 | 明确推荐对象、适用人群和核心价值 |
| P2 | 场景或状态对照 | 错误认知与真正原因 | 普通选择与有逻辑的选择 |
| P3 | 三步流程 | 核心解决框架 | 推荐或筛选框架 |
| P4 | 三条警示 | 常见卡点与执行避坑 | 避坑与不适合人群 |
| P5 | 四维度加图片槽 | 案例或视觉证据 | 真实产品、资源、案例或结果 |
| P6 | 六组横向条形图 | 判断指标 | 判断维度 |
| P7 | 三组清单加总结 | 关键结论或修正清单 | 使用建议或结论清单 |
| P8 | 八格矩阵加总结 | 行动矩阵或收藏总结 | 收藏矩阵与自然承接 |

## 七、冲突列表

### C1：共享标题硬规则与页面设计契约容量不一致

- 冲突内容：两份共享规范给出精确行数和逐行字符范围；页面设计契约对所有标题写 `recommended_lines: 2`、`max_lines: 3`，并给出不同的整字段 `max_chars`。例如 Editorial P1 共享规则允许总计 11—13 个全字符，而页面契约将中文最大字符数写为 10；Editorial P4 共享规则要求单行 6 字，页面契约则写建议 2 行、最多 3 行、最大 9 字；Swiss P1 共享规则要求 5—6 加 7—8，页面契约最大 13 字且允许最多 3 行。
- 涉及文件：`P1-P8页面设计契约总表.json`、Editorial 共享规范 V1.0、Swiss 共享规范 V1.0。
- 需要人工确认：Workbench 在标题规划与验收时，应以共享硬规则还是页面实测容量字段为最终权威；在确认前不能合并成一个自创规则。

### C2：Swiss 英文节点存在两套当前值

- 冲突内容：页面设计契约固定 P1 为 `INPUT / SYSTEM`，固定 P3 为 `SOURCE / RENDER / SHARE` 及 `SOURCE / OUTPUT`；Swiss 共享规范将 P1 改为 `SENSE → JUDGE`，P3 改为 `SENSE / JUDGE / ACT`，并明确 `INPUT / OUTPUT` 暂不使用。共享规范没有说明页面契约为何仍保留旧节点，也没有覆盖 `SYSTEM / SOURCE / RENDER / SHARE` 的迁移状态。
- 涉及文件：`P1-P8页面设计契约总表.json`、Swiss 共享规范 V1.0。
- 需要人工确认：正式模板 DOM、契约 JSON 与当前共享规则哪一层需要同步，以及 Workbench 生成方案时应输出哪组节点。

### C3：Swiss 搜索型的 P5 图片槽位缺少独立声明

- 冲突内容：页面设计契约对搜索型和推荐型 P5 都包含 `page.image.hero`；Swiss 共享规范也把 P5 定义为带图片槽的共同结构，但图片槽位契约中唯一 Swiss 槽位的 `note_mode` 仅为 `Swiss_recommendation`，没有 `Swiss_search_solution`。
- 涉及文件：`P1-P8页面设计契约总表.json`、`P1-P8图片槽位契约.json`、Swiss 共享规范 V1.0。
- 需要人工确认：搜索型是否应复用同一个 P5 图片槽位，以及图片槽位契约应如何正式表达共享范围。

### C4：Editorial P4 条目数范围不完全一致

- 冲突内容：Editorial 共享规范允许 P4 根据终稿和模板合法字段使用 4—5 条；页面设计契约当前 P4/M05 的必填列表字段是 5 条。
- 涉及文件：`P1-P8页面设计契约总表.json`、Editorial 共享规范 V1.0。
- 需要人工确认：四条内容时是否存在正式字段降级方案，还是当前 M05 实际必须五条。

### C5：账号2标题声明字符数与确定性计数不一致

- 冲突内容：正式正文文件把标题标记为 19 个全字符；按指定 Editorial 共享规范中的全字符口径，标题文本实际为 18 个字符。
- 涉及文件：账号2 `小红书笔记完整方案.md`、Editorial 共享规范 V1.0 的全字符计数定义。
- 需要人工确认：封面内容适配器应记录源声明值还是重新计算值；不得静默改写源正文。
