# Agent Note: 本地 macOS 语音伴侣

Status: implemented

[English](2026-08-22-local-macos-voice-companion.md) | 中文

## Problem

本地 macOS 包装层已经把 Harness 呈现为桌面应用，但对话仍要求用户回到主窗口并输入文字。桌面语音伴侣需要始终浮在其他应用上方，同时不能创建第二套模型配置、绕过当前会话权限，也不能把工具执行移到 Harness 之外。

## Decision

原生包装层拥有一个透明悬浮 `NSPanel`，并提供紧凑与展开两种形态。面板会出现在所有 Space、保持在普通窗口上方、支持拖动，并在 Harness 主窗口关闭后继续存活。语音轮次会打开紧凑形态，展开则保留为明确的双击操作。深蓝色不对称外壳在空闲时也会持续旋转、拉伸和改变轮廓；更明亮的电蓝流线、流沙颗粒、发光核心与麦克风振幅会区分聆听、思考、工具执行、播报与失败状态。Web 视图在“设置”右侧提供声波符号与**语音**文字，输入框为空时则显示黑色圆形声波控件。桥接层把原生发送按钮的启用状态作为最终依据，同时观察文字输入、粘贴、拖放与附件元素，因此输入文字或添加文件后，输入框控件会立即切换成黑色发送箭头。文档级按下事件处理器拥有输入框控件的可见区域，避免底层禁用的主按钮吞掉语音操作。

包装层使用 macOS Speech 框架进行实时中文转写。桥接层会在助手仍在流式输出时持续发送已经完整的短句。原生播放不等待最终回答就从第一句开始，在播放期间预生成下一句，并在回答结束后自动恢复聆听。播报期间，包装层会把带人声处理的麦克风 tap 同时交给前景能量检测器与中文局部识别任务。持续的能量，或不包含在当前播报短句中的识别结果，会成为插话：播报立即停止，桥接层触发可见的 Harness 停止控件，并在保留已经识别出的插话内容后启动正常识别。包装层会等待输入框退出占用状态，并在限定时间内重试保留的语句，仍无法提交才报告失败。单击球体也会在播报、思考或工具执行期间走同一条确定性打断路径。回答行会在语音轮次中保持隐藏，播报结束后再显示。DOM 提取会先排除思考、代码、控件与非正文元素，本地清理再移除展示语法、不可朗读字符、仅含英文的流式片段，以及中文正文之前的所有非中文块。语音清理还会把常见报告体衔接词改成简短口语，使用更小的短句，并限制单轮播报长度，同时保留完整书面回答。

在线自然语音必须由用户明确选择。用户允许后，固定版本的 `edge-tts` 会用 `zh-CN-YunxiNeural` 一次接收一个短句，并因更低的首句等待和偏日常的普通话韵律而成为优先方式。原生对话框会说明，选中用于播放的回答短句会发送到 Microsoft Edge 语音服务，而凭据、文件和完整会话不会发送。拒绝在线输出后会选择隔离的 Python 3.12 Kokoro 82M 运行环境与普通话 `zm_yunxi` 音色。由应用拥有的守护进程只加载一次模型，通过权限为 0600 的 Unix socket 接收有大小限制的请求，并在所属桌面进程 PID 消失时退出。选定的神经语音后端失败时，本轮播报会结束并恢复聆听，绝不会改用 `AVSpeechSynthesizer` 而改变音色。一个持续运行的 AVAudioEngine 音频图只加入轻微降调、均衡、短延迟与混响，不会重建输出设备。应用属性列表声明了麦克风、语音识别与文稿文件夹用途。

主框架 `WKUserScript` 会添加两个只存在于客户端内的入口，并向原生包装层公开一条私有桥接。识别出的语句通过文本框原生 value setter 与普通输入事件写入当前会话输入框，再由已有主操作提交。因此，当前会话选择的模型、工作区、权限预设、技能、凭据与工具仍然是唯一权威。桥接层只跟踪它提交的这一轮，把可见的流式输出与工具行映射为球体状态，并把增量短句交给原生语音合成。

原生菜单提供显示、隐藏与开始聆听命令。独立的按下、拖动与松开处理让单击始终可用于打断，双击改变大小，拖动移动面板；右键菜单提供相同操作。主窗口会禁止“关闭时释放”，因此从 Dock 重新唤起时仍持有有效窗口对象。关闭主窗口不会终止自身拥有的 Web 服务；退出应用仍会停止语音识别、语音播报与服务。

包装层用一条同时包含 Intel 与 Apple Silicon Homebrew 位置的明确命令搜索路径启动自身拥有的 Web 服务和更新子进程。因此，从 Finder 启动应用时，配置中安装的 Web 插件也能找到 `pnpm`、`corepack` 或 `npx`，不会只继承系统目录组成的受限路径。

语音伴侣不会直接获得通用屏幕内容、浏览器媒体或不受限制的电脑控制。页面读取与宿主操作继续使用 Harness 现有工具及其权限流程；未来的原生上下文提供方必须通过明确的 Harness 能力进入，不能在会话日志之外抓取或执行。

已经配置的 DeepSeek 与 Kimi 提供方仍是文字轮次模型。流式短句播放、自动恢复聆听与插话会改善对话轮换，但不会产生音频原生的全双工模型会话。同时进行语义音频输入与输出需要带实时音频协议的提供方能力。

## Verification

Swift 包装层可面向 arm64 macOS 13 编译，并链接 AppKit、WebKit、AVFoundation 与 Speech。独立 Swift 回归程序覆盖表情、链接、长英文或代码前缀、代码、仅含英文的流式片段、口语衔接词改写、播报回声判定与分段生成。注入桥接通过 JavaScript 语法检查。已安装应用检查覆盖左下角入口、输入框语音操作、紧凑启动、文字草稿发送控件、主窗口关闭后的独立动画、Dock 重新唤起、回环服务所有权与应用签名。在实测 Apple M4 主机上，预热后的已安装守护进程用 1.8 秒生成了 2.9 秒 WAV，常驻内存约 750 MB。插话阈值质量、主观音质与真实提供方回答仍需用户亲自试听，不属于仓库无密钥快照测试的覆盖范围。

## Alternatives considered

- **仅使用浏览器语音 API 与 DOM 浮层**：主窗口关闭后，它无法继续浮在其他应用上方，而且不同 WebKit 版本的麦克风行为不一致。系统级交互由原生 macOS 框架拥有。
- **使用独立语音模型与对话服务**：这会重复凭据，并可能与 Harness 中可见的模型、工作区和权限状态不一致。通过当前输入框提交可以保持单一会话权威。
- **由注入 JavaScript 直接调用 Harness 内部对象**：私有运行时对象会让包装层耦合浏览器实现细节。桥接只使用应用专属 Web 视图已经渲染的用户可见输入框与会话属性。
- **立即提供不受限制的屏幕与电脑访问**：这会绕过 Harness 工具审批和模型可见日志。第一版把这些操作留给现有 Harness 能力。

## Consequences

安装后的应用无需终端或第二套模型设置，就能提供可移动、可缩放并可自动继续的语音交互界面。识别依赖 macOS Speech 服务。在实测 Apple M4 主机上，本地自然语音新增约 1.3 GB 安装文件，预热进程内存约为 750 MB。在线自然语音会在用户明确同意后依赖其固定版本的 Python 运行环境和网络服务。选定的神经语音后端失败时会结束当前播报，不会切换音色。用户需要在 macOS 首次询问时授予文稿、麦克风与语音识别权限。

DOM 桥接只存在于原生包装层中；会话输入框、聊天属性或用于取消当前轮次的停止控件发生实质变化时，桥接也必须同步。神经语音输出属于普通语音合成，不是声音克隆，失败时不会改用其他系统音色。全局页面捕获与电脑操作仍不属于此功能，直到 Harness 提供明确、可记录的能力。
