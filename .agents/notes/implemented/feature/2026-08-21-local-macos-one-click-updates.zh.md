# Agent Note: 本地 macOS 一键更新

Status: implemented

[English](2026-08-21-local-macos-one-click-updates.md) | 中文

## Problem

本地 macOS 包装层启动的是已构建检出，因此关闭类似浏览器的窗口或把应用留在 Dock 中都不会更新该检出。不经常查看 GitHub 的用户可能持续运行旧构建而看不到任何提示，直接拉取则可能覆盖本地定制或与其冲突。

## Decision

原生包装层会在应用启动后检查官方 `master`，并在应用保持打开期间每六小时检查一次。只有远程头提交不是本地 `HEAD` 的祖先时，它才显示左下角的**更新**按钮；因此，本地定制提交不会产生错误的更新提示。

在 macOS 14 及以上版本中，包装层为只访问本机的 Web 视图设置空代理配置。即使已配置的系统代理不可用，页面仍可连接自身拥有的回环服务，而不会显示空白窗口。

自身拥有的 Web 服务以 `--no-open` 启动，因为页面展示由原生 Web 视图负责。该参数会关闭 CLI 通常执行的默认浏览器交接，使每次启动只显示一个应用窗口。

按钮会在修改前停止自身拥有的服务并等待其退出。内置更新程序随后验证官方 origin、`master` 分支和干净的已跟踪工作区；获取 `origin/master`；rebase 本地定制提交；安装锁文件依赖；并构建完整应用。更新程序退出后，包装层才会重启服务并重新载入 Web 视图。若 SIGTERM 八秒后仍未让服务退出，它会升级为 SIGKILL，使更新与应用拆除都等待服务完全停稳。

更新采用快速失败策略。rebase 冲突会在依赖或构建发生变化前中止。依赖安装或构建失败时，程序会把干净的已跟踪工作区重置到更新前的确切提交，并重新构建该版本。未跟踪的 Harness 状态始终留在原处。诊断内容写入随机的 0700 临时目录及其中的 0600 日志文件，只有有界的末尾片段会进入失败对话框。

## Consequences

安装后的应用无需终端即可提示官方更新，并能一键应用普通更新。检查仅在应用打开期间运行；包装层不会安装后台 launch agent，也不会在关闭期间发送系统通知。

本地源码定制必须表现为提交，自动 rebase 才能处理。未提交的已跟踪编辑会刻意阻止更新，并保持原样。真正的 rebase 冲突仍需手动解决，因为自动选择任一侧都可能丢弃官方更改或本地行为。

更新操作依赖本机已有的 Git、Node.js、Corepack 与网络访问。它更新并构建本地检出，而不是将其替换为单独签名的上游应用产物。

## Alternatives considered

- **在 Web 客户端中轮询和更新**：浏览器展示层无法安全拥有宿主 Git 进程、依赖安装、服务关闭或应用重启。把操作留在原生包装层可以保持 Web 客户端的进程边界。
- **不显示按钮而立即更新**：自动修改可能打断活跃会话，也会让本地冲突显得意外。可见的用户操作决定何时允许服务停止。
- **丢弃本地更改并重置到官方分支**：这样能简化更新程序，却会销毁定制。rebase 已提交定制可以保留它们，并在 Git 无法组合历史时安全停止。
- **常驻后台辅助程序**：它能在应用关闭期间发送通知，却会增加 launch agent、另一个生命周期所有者和持续的后台网络活动。启动检查与每六小时的应用内检查已经覆盖本地客户端的使用场景，而不增加这些负担。
